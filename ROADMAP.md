# План разработки (Roadmap)

В этом файле фиксируются этапы разработки плагина Telegram VFS. После завершения каждого этапа здесь будет появляться краткое описание того, что именно было реализовано.

## Этап 0: CI/CD и Автоматизация сборки (GitHub Actions)
- [x] Настроить проект C# (csproj) под Native AOT.
- [x] Создать workflow для GitHub Actions (сборка DLL для x86 и x64).
- [x] Настроить автоматическое создание релизов при пуше тегов (версионирование).
> **Результат:** При пуше тега `v*` GitHub автоматически собирает нативные библиотеки под обе архитектуры, переименовывает в `.wfx` и `.wfx64` и выкладывает ZIP-архив с `pluginst.inf`.

## Этап 1: Ядро, WFX API и Авторизация
- [x] Создать базовый каркас WFX-плагина.
- [x] Описать и экспортировать основные WFX-функции (`FsInit`, `FsExecuteFile`, `FsSetDirectory` и т.д.).
- [x] Подключить `WTelegramClient` и локальную базу SQLite.
- [x] Реализовать интерактивный UI для авторизации (запрос телефона, кода, 2FA).
- [x] Сохранять сессии в профиле пользователя.
> **Результат:** Плагин надежно подключается к Telegram, использует нативные окна WinForms для получения данных (без разрывов по таймауту) и сохраняет конфигурацию. Реализована принудительная подгрузка DLL SQLite через `NativeLibrary.Load()`.

## Этап 2: Корень файловой системы и Управление каналами
- [x] Создать структуру базы SQLite (таблица `mounts` для точек монтирования).
- [x] Реализовать `FsFindFirst` / `FsFindNext` для отображения корневой директории.
- [x] Добавить виртуальный элемент `[+] Создать папку` в корень.
- [x] Реализовать UI создания папки с выбором режима ("Зеркало" / "Контейнер").
> **Результат:** В корне плагина отображается меню создания, плагин умеет создавать приватные каналы в Telegram (с префиксом `[TC]`) и сохранять их как точки монтирования в локальную БД.

## Этап 3: Навигация и Чтение содержимого каналов
- [x] Корректный вход внутрь папки-канала (`FsSetDirectory`).
- [x] Автоматическое переключение соседней панели TC на локальный путь (при входе в папку режима "Зеркало").
- [x] Отображение списка файлов внутри канала (чтение напрямую из таблицы `files` локальной БД SQLite).
- [ ] Механизм первоначальной/ручной синхронизации БД с историей канала Telegram (для работы с разных устройств).

## Этап 4: Базовые файловые операции и Корзина
- [ ] Скачивание файлов из Telegram в локальную систему (`FsGetFile`).
- [ ] Загрузка локальных файлов в Telegram-канал (`FsPutFile`).
- [ ] Виртуальная корзина (`[.Trash]`) вместо безвозвратного удаления файлов (`FsDeleteFile`).
- [ ] Механизм редактирования файлов (выгрузка во temp, отслеживание изменений, загрузка обновленной версии в Telegram).
- [ ] Сохранение предыдущих версий отредактированных файлов в виртуальной корзине.

## Этап 5: Поддержка вложенных папок (Виртуальная иерархия)
- [ ] Реализовать хранение путей к файлам в БД (эмуляция подпапок внутри канала).
- [ ] Создание и удаление виртуальных папок (`FsMkDir`, `FsRemoveDir`).
- [ ] Перемещение и переименование файлов и папок (`FsRenMovFile`).

## Этап 6: Режимы, Ограничения и Полировка
- [ ] Полноценная логика двусторонней синхронизации для режима "Зеркало" (отслеживание изменений в локальной папке).
- [ ] Обработка лимитов размера файлов Telegram (разбиение или блокировка: 2 ГБ для обычных / 4 ГБ для Premium).
- [ ] (Опционально) Шифрование файлов перед отправкой для режима "Контейнер".
