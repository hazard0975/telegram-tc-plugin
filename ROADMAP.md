## Этап 4: Базовые файловые операции и Корзина
- [x] Скачивание файлов из Telegram в локальную систему (`FsGetFile`).
- [x] Загрузка локальных файлов в Telegram-канал (`FsPutFile`).
- [x] Запуск, открытие ассоциированными программами и редактирование файлов (`FsExecuteFile` / `FS_EXEC_YOURSELF` / `F4`).
- [x] Виртуальная глобальная корзина (`[🗑] Корзина`) на корневом уровне плагина для предотвращения нежелательной двусторонней синхронизации в Total Commander (`FsDeleteFile`, `FsRemoveDir`).
- [x] Сохранение и версионный просмотр файлов из корзины с суффиксом `_vN.ext` (`FsGetFile`).
- [x] Восстановление файлов и папок в исходное расположение (`Alt+Enter` -> кнопка «Восстановить» в диалоге свойств).
- [x] Навигационные кнопки в свойствах по `Alt+Enter` для мгновенной навигации в активной панели: «Корзина» (для активных файлов), «К папке» / «К файлу» (для файлов корзины), «К каналу» (для корзины канала) через `Win32Api.NavigateToVfsPath`.
- [x] Статистика и полная очистка корзины с пакетным удалением сообщений из Telegram (`TelegramManager.DeleteMessagesAsync` с батчингом по 100 сообщений, защитой от дубликатов через группировку `GroupBy`, подсчетом ссылок `FilterMessagesWithoutActiveReferences` для защиты оригиналов, каскадным удалением вложенных файлов папок и барьерами `try/catch` для стабильности Total Commander).
- [ ] Автоматическая оптимизация размера БД SQLite: выполнение `PRAGMA incremental_vacuum;` при полной очистке виртуальной корзины или удалении каналов (`DeleteMount`).
> **Промежуточный результат:** 
> 1. Реализована отправка файлов в Telegram через `FsPutFile` и `FsPutFileW`. Файлы передаются как несжатые документы (`InputMediaUploadedDocument`) с сохранением исходного имени и установкой страховочной подписи (caption) с относительным путем. Реализован отзывчивый цикл ожидания в потоке Total Commander с интервалом 50 мс и вызовом `ReportProgress`, обеспечивающий мгновенный отклик кнопок «Отмена», «Пауза» и «В фон». Реализована физическая пауза и отмена сетевой передачи через `PausableStream` и токен отмены, проверка лимитов Telegram (2 ГБ / 4 ГБ с Premium), обработка флага перезаписи (`FS_COPYFLAGS_OVERWRITE`) с переносом старой версии в корзину (`in_trash = 1`) и инкрементом версии (`ver + 1`), а также автообновление панели через `Win32Api.RefreshActivePanel()`. В SQLite включен WAL-режим (`journal_mode=WAL`) с умной системой сброса `TriggerCheckpoint`: при массовой выгрузке 20 файлов сброс журнала выполняется ровно 1 раз по сигналу `FS_STATUS_END` от Total Commander, при одиночных операциях работает таймер с отсрочкой (debounce 1.5s), а при выходе из Total Commander через событие `.NET` `ProcessExit` гарантированно очищаются пулы подключений `SqliteConnection.ClearAllPools()` и ужимается WAL-файл.
> 2. Реализовано скачивание файлов из Telegram через `FsGetFile` и `FsGetFileW`. Загрузка выполняется через низкоуровневый MTProto API (`Upload_GetFile`) по `tg_message_id` в промежуточный файл `.tgpart`. Обеспечена полноценная поддержка докачки (Resume) при обрыве или отмене скачивания (файл `.tgpart` сохраняется, а следующий старт подхватывает уже загруженный фрагмент с выравниванием по границе чанка `FilePartSize`, исключая перезакачку и раздувание файла). Реализована оптимизация для пакетных операций и синхронизации: если целевой локальный файл уже существует и совпадает по размеру и `MTime`, скачивание мгновенно возвращает успех без траты трафика. По завершении скачивания на локальном файле восстанавливается точная дата изменения (`File.SetLastWriteTimeUtc`). Реализован неблокирующий цикл ожидания в потоке Total Commander с интервалом 50 мс, гарантирующий постоянную отзывчивость кнопок «Отмена», «Пауза» и закрытия диалога [X]. Внедрен шлюз паузы на `ManualResetEventSlim`, мгновенно останавливающий сетевой трафик и запись на диск при постановке на паузу в Total Commander.
> 3. Реализован полный набор экспортов для многопоточности и фонового режима: `FsGetBackgroundFlags`, `FsGetBackgroundFlagsW` (возвращают `BG_DOWNLOAD | BG_UPLOAD`), `FsStatusInfo`, `FsStatusInfoW` (обработка жизненного цикла операций плагина), а также нативный Unicode-вход `FsInitW`. Это активирует в Total Commander нативную поддержку кнопки **«В фоне» («Background»)**, фонового диспетчера передачи (BTM) и очереди (F2).
> 4. Реализован стандартный запуск файлов по **Enter** и двойному клику через `FsExecuteFile` / `FsExecuteFileW`: плагин возвращает код `FS_EXEC_YOURSELF (-1)`, благодаря чему Total Commander автоматически скачивает файл во временную директорию и открывает его в системном приложении Windows. Поддержано редактирование по **F4**: после закрытия внешнего редактора Total Commander автоматически отправляет обновленный файл обратно в Telegram через `FsPutFile`. Реализовано нативное информационное окно свойств файла/папки по **Alt+Enter** (`FilePropertiesDialog`) с детальными параметрами из SQLite (канал, путь, размер в байтах, дата, ID сообщения в Telegram, версия ревизии, статус корзины и UID) с возможностью быстрого копирования отчета в буфер обмена.
> 5. Реализована полнофункциональная подсистема **Корзины (`[🗑] Корзина`)**: виртуальная папка доступна в корне каждого канала. Удаленные файлы и перезаписанные версии документов выводятся с суффиксом ревизии `_vN.ext`, могут быть одновременно открыты и сопоставлены с актуальными файлами. По `Alt+Enter` на файле доступно моментальное восстановление в исходный каталог канала с автосозданием родительской структуры (включая автоматическое каскадное восстановление вложенных файлов для виртуальных папок, динамически воссозданных по путям удаленных файлов). Поддержано массовое выделение и восстановление файлов и папок через **`F5` / `F6` (или Drag-and-Drop)** из корзины в любую папку VFS с возвратом чистых имен. При восстановлении всей папки из Корзины восстанавливается исключительно самая свежая версия каждого файла (`ROW_NUMBER() OVER (...)`), а предыдущие ревизии остаются в Корзине. Внедрена автоматическая санитарная очистка дубликатов активных файлов с одинаковыми именами. При копировании/скачивании файлов на локальный диск Windows (`F5`/`F6` на `D:\...`) плагин автоматически очищает суффикс версии (`_v1`, `_v2`), сохраняя чистый оригинальный файл на диск. По `Alt+Enter` или `F8` на корзине доступен просмотр объёма и безвозвратная пакетная очистка (как записей SQLite, так и сообщений в Telegram через батчинг по 100 сообщений).


## Этап 5: Поддержка вложенных папок (Виртуальная иерархия)
- [x] Реализовать хранение путей к файлам в БД (эмуляция подпапок внутри канала).
- [x] Создание и удаление виртуальных папок (`FsMkDir`, `FsMkDirW`, `FsRemoveDir`, `FsRemoveDirW`).
- [x] Перемещение и переименование файлов и папок (`FsRenMovFile`, `FsRenMovFileW`).
> **Результат:** Реализована полноценная поддержка многоуровневых вложенных виртуальных папок и гибридных манипуляций с ними (F5 / F6). Функция `CreateStateForPath` парсит произвольную глубину путей (например `\Channel\Folder1\Subfolder2`), извлекает `parent` относительный путь и корректно запрашивает содержимое из SQLite. Внедрена функция универсальной нормализации путей `NormalizeVfsPath` для корректного отсечения префикса тома/плагина (`\\\tgvfsplugin\`) и поддержка регистронезависимого поиска в SQLite (`COLLATE NOCASE`). Исправлена сигнатура вызова `FsRenMovFile` / `FsRenMovFileW` (приведена к полному 5-параметрическому стандарту `stdcall` WFX API), устранившая сбои памяти (`Access Violation c0000005`) при переименовании в Total Commander 7.50a+. Реализовано четкое разделение операций по флагу `isMove`: при нажатии **F5 (или обычном drag-and-drop)** выполняется быстрое виртуальное копирование в SQLite с нулевым расходом трафика, а при **F6 (или Shift+drag)** — честное перемещение с обновлением путей. Экспортированы нативные ANSI и Unicode обработчики `FsMkDir` / `FsMkDirW` для создания каталогов по кнопке F7 с авто-созданием родительских папок (`EnsureParentDirectoriesExist`). Выгрузка и скачивание учитывают подпути. Удаление виртуальных подпапок (`FsRemoveDir` / `FsDeleteFile`) каскадно помечает `in_trash = 1` для всего поддерева. Реализованы нативные экспорты `FsRenMovFile` / `FsRenMovFileW` с гибридной логикой: перемещение/переименование/копирование внутри одного канала происходит мгновенно в базе SQLite, а между разными каналами безопасно перекачивает файл во временное хранилище и создает новое сообщение в целевом Telegram-канале с обновлением SQLite.

- [x] Умная синхронизация по источникам (Smart Sync & Origin Tracking) для режима "Контейнер": фиксация `source_path`, проверка обновлений на диске, кнопка «Найти на ПК» и кнопка «Smart Sync» в свойствах папки/канала (`Alt+Enter`), вызов свойств и Smart Sync для текущей папки по `Alt+Enter` на верхнем элементе `..`, полнофункциональный диалог `SmartSyncDialog` с 7 колонками в стиле синхронизации каталогов Total Commander, интерактивными многострочными подсказками по всей ширине строки и автосохранением колонок, WFX Content-поле `[=<fs>.SourcePath]`.
- [x] Стандартизация геометрии и верстки всех нативных UI-диалогов плагина (`CreateFolderDialog`, `DeleteFolderDialog`, `InputDialog`, `SettingsDialog`, `FilePropertiesDialog`, `SmartSyncDialog`): единая система отступов (20px слева/справа, 16px сверху/снизу), динамическое привязывание (Anchors), выравнивание нижней панели кнопок (Height 52px, с кнопками справа) и фиксированный расчет `ClientSize` для единообразного нативного вида во всех окнах.

- [ ] Полноценная логика двусторонней синхронизации для режима "Зеркало" (отслеживание изменений в локальной папке).
- [ ] Обработка лимитов размера файлов Telegram (разбиение или блокировка: 2 ГБ для обычных / 4 ГБ для Premium).
- [ ] (Опционально) Шифрование файлов перед отправкой для режима "Контейнер".
> **Промежуточный результат:** 
> 1. Полностью переработана подсистема логирования (`Logger.cs`). Все события и файловые операции плагина (`FsPutFile`, `FsGetFile`, `FsDeleteFile`, `FsRenMovFile`, `FsMkDir`, `TelegramManager`, `VfsDatabase`, `SettingsManager`, UI) переведены на единый структурированный формат с уровнями, тегами категорий, понятными сообщениями цепочки событий, форматированием байтов и полным выводом исключений.
> 2. Внедрен полный стек WFX Content Plugin API (`FsContentGetSupportedField`, `FsContentGetSupportedFieldW`, `FsContentGetSupportedFieldFlags`, `FsContentGetDefaultSortOrder`, `FsContentGetValue`, `FsContentGetValueW`, `FsContentGetDefaultView`, `FsContentGetDefaultViewW`). Плагин предоставляет поля `Version` (число), `VersionName` (`v1`, `v2`), `FileName` (оригинальное имя), `TgMessageId` и `SourcePath` (оригинальный путь на диске ПК). Запросы разрешаются мгновенно из локального SQLite кэша без сетевых запросов к Telegram. Total Commander может использовать эти поля как в настраиваемых всплывающих подсказках (tooltips), так и в пользовательских наборах колонок (Custom Columns View).
> 3. Реализован механизм **Умной синхронизации (Smart Sync & Origin Tracking)** для режима «Контейнер»: в базе данных SQLite добавлена колонка `source_path` с автоматической миграцией схемы, при выгрузке (`FsPutFile`) сохраняется полный путь к оригинальному файлу на диске ПК. В диалоге свойств файлов (`FilePropertiesDialog` по `Alt+Enter`) добавлено отображение пути источника и кнопка «Найти на ПК», открывающая файл в Проводнике Windows. В свойствах каталогов и корня канала добавлена кнопка «Smart Sync», запускающая сканирование дерева файлов и диалог `SmartSyncDialog`. В диалоге сопоставляются размеры и Unix-timestamp (с допуском ±2 сек), определяются статусы («На ПК новее», «В TG новее», «Идентичны», «Не найден на ПК») и поддерживается пакетное обновление выбранных файлов в обоих направлениях с автоматическим версионированием старых копий в Telegram VFS.
