# План разработки (Roadmap)

В этом файле фиксируются этапы разработки плагина Telegram VFS. После завершения каждого этапа здесь будет появляться краткое описание того, что именно было реализовано.

## Этап 0: CI/CD и Автоматизация сборки (GitHub Actions)
- [x] Настроить проект C# (csproj) под Native AOT.
- [x] Создать workflow для GitHub Actions (сборка DLL для x86 и x64).
- [x] Настроить автоматическое создание релизов при пуше тегов (версионирование).
> **Результат:** При пуше тега `v*` GitHub автоматически собирает нативные библиотеки под обе архитектуры, переименовывает в `.wfx` и `.wfx64` и выкладывает ZIP-архив с `pluginst.inf`.

## Этап 4: Базовые файловые операции и Корзина
- [x] Скачивание файлов из Telegram в локальную систему (`FsGetFile`).
- [x] Загрузка локальных файлов в Telegram-канал (`FsPutFile`).
- [ ] Виртуальная корзина (`[.Trash]`) вместо безвозвратного удаления файлов (`FsDeleteFile`).
- [ ] Автоматическая оптимизация размера БД SQLite: выполнение `PRAGMA incremental_vacuum;` при полной очистке виртуальной корзины `[.Trash]` или удалении каналов (`DeleteMount`).
- [ ] Механизм редактирования файлов (выгрузка во temp, отслеживание изменений, загрузка обновленной версии в Telegram).
- [ ] Сохранение предыдущих версий отредактированных файлов в виртуальной корзине.
> **Промежуточный результат:** 
> 1. Реализована отправка файлов в Telegram через `FsPutFile` и `FsPutFileW`. Файлы передаются как несжатые документы (`InputMediaUploadedDocument`) с сохранением исходного имени и установкой страховочной подписи (caption) с относительным путем. Реализован отзывчивый цикл ожидания в потоке Total Commander с интервалом 50 мс и вызовом `ReportProgress`, обеспечивающий мгновенный отклик кнопок «Отмена», «Пауза» и «В фон». Реализована физическая пауза и отмена сетевой передачи через `PausableStream` и токен отмены, проверка лимитов Telegram (2 ГБ / 4 ГБ с Premium), обработка флага перезаписи (`FS_COPYFLAGS_OVERWRITE`) с переносом старой версии в корзину (`in_trash = 1`) и инкрементом версии (`ver + 1`), а также автообновление панели через `Win32Api.RefreshActivePanel()`. В SQLite включен WAL-режим (`journal_mode=WAL`) с умной системой сброса `TriggerCheckpoint`: при массовой выгрузке 20 файлов сброс журнала выполняется ровно 1 раз по сигналу `FS_STATUS_END` от Total Commander, при одиночных операциях работает таймер с отсрочкой (debounce 1.5s), а при выходе из Total Commander через событие `.NET` `ProcessExit` гарантированно очищаются пулы подключений `SqliteConnection.ClearAllPools()` и ужимается WAL-файл.
> 2. Реализовано скачивание файлов из Telegram через `FsGetFile` и `FsGetFileW`. Загрузка выполняется через низкоуровневый MTProto API (`Upload_GetFile`) по `tg_message_id` в промежуточный файл `.tgpart`. Обеспечена полноценная поддержка докачки (Resume) при обрыве или отмене скачивания (файл `.tgpart` сохраняется, а следующий старт подхватывает уже загруженный фрагмент с выравниванием по границе чанка `FilePartSize`, исключая перезакачку и раздувание файла). Реализована оптимизация для пакетных операций и синхронизации: если целевой локальный файл уже существует и совпадает по размеру и `MTime`, скачивание мгновенно возвращает успех без траты трафика. По завершении скачивания на локальном файле восстанавливается точная дата изменения (`File.SetLastWriteTimeUtc`). Реализован неблокирующий цикл ожидания в потоке Total Commander с интервалом 50 мс, гарантирующий постоянную отзывчивость кнопок «Отмена», «Пауза» и закрытия диалога [X]. Внедрен шлюз паузы на `ManualResetEventSlim`, мгновенно останавливающий сетевой трафик и запись на диск при постановке на паузу в Total Commander.
> 3. Реализован полный набор экспортов для многопоточности и фонового режима: `FsGetBackgroundFlags`, `FsGetBackgroundFlagsW` (возвращают `BG_DOWNLOAD | BG_UPLOAD`), `FsStatusInfo`, `FsStatusInfoW` (обработка жизненного цикла операций плагина), а также нативный Unicode-вход `FsInitW`. Это активирует в Total Commander нативную поддержку кнопки **«В фоне» («Background»)**, фонового диспетчера передачи (BTM) и очереди (F2).

## Этап 5: Поддержка вложенных папок (Виртуальная иерархия)
- [x] Реализовать хранение путей к файлам в БД (эмуляция подпапок внутри канала).
- [x] Создание и удаление виртуальных папок (`FsMkDir`, `FsMkDirW`, `FsRemoveDir`, `FsRemoveDirW`).
- [x] Перемещение и переименование файлов и папок (`FsRenMovFile`, `FsRenMovFileW`).
> **Результат:** Реализована полноценная поддержка многоуровневых вложенных виртуальных папок и гибридных манипуляций с ними (F5 / F6). Функция `CreateStateForPath` парсит произвольную глубину путей (например `\Channel\Folder1\Subfolder2`), извлекает `parent` относительный путь и корректно запрашивает содержимое из SQLite. Внедрена функция универсальной нормализации путей `NormalizeVfsPath` для корректного отсечения префикса тома/плагина (`\\\tgvfsplugin\`) и поддержка регистронезависимого поиска в SQLite (`COLLATE NOCASE`). Исправлена сигнатура вызова `FsRenMovFile` / `FsRenMovFileW` (приведена к полному 5-параметрическому стандарту `stdcall` WFX API), устранившая сбои памяти (`Access Violation c0000005`) при переименовании в Total Commander 7.50a+. Реализовано четкое разделение операций по флагу `isMove`: при нажатии **F5 (или обычном drag-and-drop)** выполняется быстрое виртуальное копирование в SQLite с нулевым расходом трафика, а при **F6 (или Shift+drag)** — честное перемещение с обновлением путей. Экспортированы нативные ANSI и Unicode обработчики `FsMkDir` / `FsMkDirW` для создания каталогов по кнопке F7 с авто-созданием родительских папок (`EnsureParentDirectoriesExist`). Выгрузка и скачивание учитывают подпути. Удаление виртуальных подпапок (`FsRemoveDir` / `FsDeleteFile`) каскадно помечает `in_trash = 1` для всего поддерева. Реализованы нативные экспорты `FsRenMovFile` / `FsRenMovFileW` с гибридной логикой: перемещение/переименование/копирование внутри одного канала происходит мгновенно в базе SQLite, а между разными каналами безопасно перекачивает файл во временное хранилище и создает новое сообщение в целевом Telegram-канале с обновлением SQLite.
