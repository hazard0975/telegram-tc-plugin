# План разработки (Roadmap)

В этом файле фиксируются этапы разработки плагина Telegram VFS. После завершения каждого этапа здесь будет появляться краткое описание того, что именно было реализовано.

## Этап 0: CI/CD и Автоматизация сборки (GitHub Actions)
- [x] Настроить проект C# (csproj).
- [x] Создать workflow для GitHub Actions, который будет автоматически собирать плагин (Native AOT для x86 и x64).
- [x] Настроить автоматическое создание релизов (GitHub Releases) при пуше новых тегов (версионирование).
> **Результат:** Создан `release.yml`. При пуше тега `v*` GitHub автоматически соберет нативную DLL под обе архитектуры, переименует их в `.wfx` и `.wfx64`, запакует в ZIP вместе с установщиком и выложит в релизы.

## Этап 1: Каркас WFX-плагина
- [x] Создать базовую структуру проекта.
- [x] Описать P/Invoke обертки (экспортируемые функции `FsInit`, `FsFindFirst` и т.д., которые требует Total Commander).
- [x] Добиться успешной компиляции "пустышки", которую TC увидит в списке плагинов.
> **Результат:** Написан C#-проект `TgVfsPlugin.csproj` с поддержкой Native AOT. Создан класс `WfxExports.cs` с четырьмя обязательными функциями (`FsInit`, `FsFindFirst`, `FsFindNext`, `FsFindClose`), экспортируемыми по стандарту `stdcall`. Добавлен файл `pluginst.inf` для автоматической установки в TC.
