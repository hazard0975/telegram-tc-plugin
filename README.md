# Telegram VFS Plugin (Total Commander)

Архитектурный концепт WFX-плагина для Total Commander, позволяющего работать с личным Telegram-каналом как с виртуальной файловой системой (VFS).

## 1. Ядро и технологии
* **Язык/Платформа:** C# (.NET 9+).
* **Библиотека Telegram:** `WTelegramClient` (MTProto API).
* **Формат сборки:** Нативная DLL для Windows через **Native AOT** (не требует установки .NET Framework у пользователя).
* **Сборка и CI/CD:** Компиляция и версионирование осуществляются автоматически через **GitHub Actions**. Итоговые артефакты (готовые `.zip` архивы с плагинами `.wfx` и `.wfx64`) публикуются в GitHub Releases.
* **Фундаментальный принцип изолированности (Strict Plugin-Only):** Работа с каналами плагина ведется **строго и исключительно через Total Commander и сам плагин**. Никакие файлы не добавляются и не редактируются пользователем через сторонние клиенты Telegram (смартфоны, веб или десктоп). Telegram выступает исключительно в роли бессерверного блочного/файлового облачного бэкенда (Cloud Object Storage). Все метаданные, структура каталогов, точные даты модификации файлов (`mtime`), размеры, версии и локальные пути-источники (`source_path`) являются прерогативой базы данных SQLite плагина, что гарантирует абсолютную точность без каких-либо искажений со стороны мессенджера.

## 2. Локальный движок (SQLite)
Для обеспечения нулевой задержки (0 мс) при навигации используется локальная база данных SQLite. Плагин оперирует множеством подключений, каждое из которых соответствует отдельному Telegram-каналу.

* **Таблица `mounts` (Точки монтирования / Каналы):**
  * `id` (уникальный идентификатор, например `tg-fldr-123`)
  * `local_path` (привязанный локальный путь на ПК, для режима Зеркало)
  * `channel_id` (ID приватного канала в Telegram)
  * `channel_name` (название папки/канала)
  * `mode` (Режим работы: `0` - Зеркало, `1` - Контейнер)
  * `created_at` (дата создания, Unix Timestamp в миллисекундах, INTEGER)
  * `in_trash` (флаг нахождения канала в Корзине: `0` - активный канал в корне плагина, `1` - перемещен в Корзину, INTEGER)

* **Таблица `files` (Структура файлов и папок - Adjacency List):**
  * `uid` (уникальный идентификатор файла/папки)
  * `mount_id` (ID точки монтирования из таблицы `mounts`)
  * `isdir` (папка или файл)
  * `name` (имя файла/папки)
  * `parent` (относительный путь к родительской папке, например `docs/2026`, либо null/''/false для корня канала)
  * `mtime` (дата модификации, Unix Timestamp в миллисекундах, INTEGER)
  * `size` (размер файла)
  * `tg_message_id` (ID сообщения в Telegram)
  * `in_trash` (флаг удаления, boolean)
  * `ver` (версия файла)
  * `source_path` (исходный локальный путь на ПК при выгрузке, например `D:\Music\ABBA\HappyNewYear.mp3`, TEXT)
  * Индекс `idx_files_mount_parent` по полях `(mount_id, parent, in_trash)` для мгновенного выполнения иерархических запросов.

## 3. Режимы работы и Управление каналами
* **Менеджер подключений (Корень плагина):** В корневой директории плагина (`\\tgvfsplugin\`) не хранятся файлы. Там находятся:
  * Служебный триггер `[📁+] Создать папку` — при клике открывается диалог создания папки/канала с полем ввода имени, выбором локального пути через системный диалог «Обзор...» (с автозаполнением имени папки или корня диска `Диск (D)`) и переключателем режима (Зеркало/Контейнер).
  * Служебный триггер `[❌] Удалить папку` — осознанное административное действие: при клике открывается диалог выбора виртуальной папки (отображаются как активные каналы, так и каналы с меткой `[в Корзине]`), после чего выводится модальное окно подтверждения с явным предупреждением о том, что удаление физически удалит канал и все файлы в Telegram. При подтверждении канал мгновенно удаляется в Telegram через API WTelegramClient (`Channels_DeleteChannel`), а записи удаляются из базы SQLite.
  * Служебный триггер `[⚙] Настройки` — при клике открывается окно конфигурации.
  * Список подключенных папок. Поддерживается безопасная двухэтапная модель удаления каналов:
    * **Удаление в корне (`F8` / `Delete` на канале в `\\tgvfsplugin\`):** Не выдаёт блокирующих предупреждений и не затрагивает Telegram. Канал и все его файлы мгновенно помечаются `in_trash = 1` и безопасно перемещаются в `[🗑] Корзина`.
    * **Окончательное удаление канала из Telegram:** Выполняется через пункт `[❌] Удалить папку` в корне плагина. Попытка нажать `F8` на корневой папке канала внутри `[🗑] Корзина` блокируется с информативным сообщением во избежание пофайлового стирания сообщений клиентом Total Commander.
* **Режим "Зеркало" (Бэкап):** Жестко привязывается к локальной папке на ПК (сохраняется в `local_path`). При интерактивном входе в Зеркало в плагине, соседняя панель Total Commander автоматически переключается на `local_path`. Плагин определяет сторону расположения VFS-панели через анализ элементов пути `TPathBox` и фокус Win32 API (`GetWindowRect`), отправляя сообщение `WM_COPYDATA` (команда `CD`) с разделителем `\r` строго в противоположную локальную панель. Для полной поддержки кириллицы и любых Unicode-символов в путях (в версиях Total Commander 7.50a+) путь передается в кодировке UTF-8 с обязательным префиксом UTF-8 BOM (`0xEF, 0xBB, 0xBF`), что исключает искажение символов кодовой страницей ANSI. При пакетных операциях копирования, перемещения и создания каталогов (Drag-and-Drop, `FsPutFile`, `FsMkDir`, `_isBatchOperation`) автоматическая смена каталога и перезапись зеркального пути блокируются, предотвращая сбои навигации и ошибочные переключения панелей. Идеально для использования штатной функции TC "Синхронизировать каталоги".
* **Режим "Контейнер" (Флешка):** Обычная виртуальная папка без привязки к локальному пути. Соседняя панель при навигации не затрагивается.
* **Хранилище в Telegram:** Каждая созданная папка создает **отдельный приватный канал** в Telegram. Для порядка в мессенджере каналам автоматически добавляется префикс `[TC]` (например, `[TC] MyBackup`), который скрывается при отображении в Total Commander.
* **Авторизация и 2FA:** Сессия пользователя сохраняется локально в `.session` файл (в `%APPDATA%\TelegramVFS`). Поддерживается полная цепочка входа: Номер телефона -> Код из Telegram -> 2FA пароль.
* **Метаданные (База в канале):** В каждый созданный канал плагин загружает слепок SQLite-базы, относящийся только к этому каналу, и закрепляет (Pin) сообщение. На другом ПК при входе плагин считывает эти закрепленные сообщения и мгновенно восстанавливает структуру всех зеркал и контейнеров.

## 4. Механики безопасности и отказоустойчивости
* **Страховочные подписи (Captions):** При загрузке файла в Telegram, в подпись (caption) сообщения записывается относительный путь (например, `docs/2026/info.txt`). Это позволит написать скрипт-восстановитель, если SQLite-база будет безвозвратно утеряна.
* **Виртуальная корзина `[🗑] Корзина`:** 
  - Размещается на самом верхнем уровне плагина (в корне) как отдельная папка `[🗑] Корзина` (сиблинг к папкам активных каналов). Такое расположение полностью исключает нежелательное попадание удаленных объектов в двустороннюю синхронизацию каталогов в Total Commander.
  - При удалении файлов или папок клавишей `F8`/`Delete` в Total Commander (`FsDeleteFile` / `FsRemoveDir`) либо при перезаписи файлов новыми версиями, сообщения в Telegram физически не удаляются. В базе SQLite запись помечается `in_trash = 1` и перемещается в виртуальную корзину.
  - **Иерархия папок в корзине:** Внутри корневой папки `[🗑] Корзина` находятся подпапки для каждого канала (например, `[🗑] Корзина\MyChannel`). При входе в них отображается точная иерархия каталогов удалённых элементов. При навигации вглубь удалённых папок отображаются только их дочерние элементы.
  - **Навигация и версионный просмотр:** Внутри папки `[🗑] Корзина` отображаются все удаленные файлы и их предыдущие версии с автоматическим суффиксом ревизии: `имя_файла_vN.расширение` (например, `document_v1.docx`, `document_v2.docx`). По нажатию `Enter` или двойному клику файл открывается ассоциированной программой (или по `F3` во встроенном Lister) с точным версионным именем, что позволяет одновременно открыть и сравнить текущую версию документа с удаленной или старой версией из корзины.
  - **Восстановление файлов и массовое перемещение (`Alt+Enter` / `F5` / `F6` / Drag-and-Drop):** 
    - При вызове свойств (`Alt+Enter`) на отдельном файле внутри корзины открывается диалог `FilePropertiesDialog` с кнопкой `[ Восстановить ]` для одиночного восстановления. В окне свойств корзины канала или её подпапок доступна кнопка `[ Восстановить ]` для быстрой массовой реставрации всех удалённых элементов со всеми родительскими каталогами обратно в активную VFS.
    - При выделении нескольких файлов или папок внутри `[🗑] Корзина` восстановление выполняется массово через нативные клавиши Total Commander: **`F6` (Переместить)** или **`F5` (Копировать)** в любую обычную папку VFS (или мышкой Drag-and-Drop). Плагин рекурсивно снимает флаг корзины `in_trash = 0` только для самых свежих версий файлов (`ROW_NUMBER() OVER (...)`), оставляя предыдущие ревизии (`_v1`) в Корзине и возвращая восстанавливаемые элементы на свои места с их оригинальными чистыми именами. При инициализации базы и восстановлении выполняется автоматическая санитарная очистка дубликатов активных файлов.
    - При копировании/скачивании из корзины или VFS на локальный диск Windows (`F5`/`F6` на `D:\...`) плагин автоматически очищает суффикс версии (`_v1`, `_v2`), сохраняя на диск диска чистый исходный файл (например, `aimp_lastfm.dll`).
  - **Связанная навигация между активной VFS и Корзиной (Properties Teleportation):**
    - По нажатию `Alt+Enter` (вызов свойств файла) плагин добавляет в нативный диалог специальную панель переходов, позволяющую мгновенно переключать текущую активную панель Total Commander через Win32 API (`Win32Api.NavigateToVfsPath` с командой `WM_COPYDATA` / `CD`).
    - Для активного файла/папки выводится кнопка **«Корзина»** — она мгновенно открывает максимально возможную существующую подпапку в корзине (если в целевой подпапке удалений не было, плагин автоматически поднимается по иерархии до ближайшего родительского каталога с удалёнными файлами, либо до корня корзины канала).
    - Для файла/папки в корзине выводятся кнопки **«К папке»** или **«К файлу»** — они мгновенно находят и открывают исходное расположение в активной VFS на текущей панели. Если исходное расположение было удалено или перемещено, плагин безопасно предупреждает сообщением: *"Исходное расположение больше не существует в активном хранилище."*
    - Для корзины канала выводится кнопка **«К каналу»** — она переключает текущую панель на корень соответствующего активного канала.
    - Навигация выполняется строго в текущей активной панели пользователя, обеспечивая 100% стабильность и предсказуемость в любых сценариях, включая «режим зеркала».
  - **Очистка корзины и удаление навсегда:** 
    - При нажатии `Alt+Enter` на самой папке `[🗑] Корзина\ChannelName` открывается окно статистики (количество удаленных файлов, суммарный объем в байтах) с кнопкой `[ ♻ Очистить корзину ]`.
    - **Пофайловое удаление по F8 в корзине:** Внутри корзины активного канала разрешено удаление отдельных файлов (`_v1.ext`) или подпапок клавишей `F8`/`Delete` (Total Commander запрашивает подтверждение, после чего плагин удаляет соответствующие сообщения из Telegram и записи из БД).
    - **Защита каналов в корзине от F8:** Если канал находится в корзине (`in_trash = 1`), удаление файлов и подпапок по `F8` внутри него жестко блокируется (`FsDeleteFile` / `FsRemoveDir` возвращают отказ `0`). Это исключает пофайловое стирание сообщений из Telegram при нажатии `F8` на папке канала в корзине. Окончательное уничтожение канала и всех его сообщений производится только через осознанный пункт `[❌] Удалить папку` в корне плагина.
    - При удалении клавишей `F8`/`Delete` внутри корзины или при полной очистке корзины плагин отправляет запросы на удаление в Telegram пакетами до 100 сообщений за один API-вызов с паузой `250 мс` между чанками для предотвращения сетевой блокировки `FLOOD_WAIT`.
    - **Защита оригиналов и подсчёт активных ссылок (Reference Protection):** если файл был скопирован в другие папки VFS или дублирован (несколько записей `uid` ссылаются на один и тот же `tg_message_id`), при окончательной очистке корзины физическое сообщение в Telegram **НЕ удаляется**, пока в файловой системе остаётся хотя бы одна активная ссылка на него (`FilterMessagesWithoutActiveReferences`). Физическое удаление из Telegram происходит только тогда, когда удалена последняя ссылка/копия.
    - **Каскадная очистка поддерева папок:** при удалении папки из корзины плагин рекурсивно извлекает все вложенные файлы (`GetTrashSubTreeFiles`), проверяет наличие живых ссылок и пачками удаляет сообщения из Telegram, после чего очищает записи в SQLite.
    - **Прогресс-бар и Отмена:** Каждая пачка отчитывается в Total Commander через `ReportProgress`, с поддержкой мгновенной отмены операции кнопкой «Отмена».
    - **Устойчивость к исключениям:** Все операции очистки корзины и нативные точки входа `FsStatusInfo` / `FsStatusInfoW` защищены блоками `try/catch`, исключая сбои и падения хост-процесса Total Commander.
* **Сборщик мусора (Temp):** Скачанные для предпросмотра (F3) файлы падают в `%TEMP%/TgPluginCache`. При старте плагин очищает кэш от файлов старше 7 дней или если общий объем превышает 5 ГБ.

## 5. Важные технические нюансы реализации
1. **Режим WAL для SQLite и умный сброс (Batch Checkpoint):** Включен `PRAGMA journal_mode=WAL;`, чтобы фоновое копирование (BTM) не блокировало базу и интерфейс TC при параллельной навигации. Реализована система умного сброса `TriggerCheckpoint`: при пакетных операциях (выгрузка списка из N файлов) одиночные сбросы пропускаются, и выполняет 1 неблокирующий чекпоинт (`PRAGMA wal_checkpoint(PASSIVE);`) по событию `FS_STATUS_END` от Total Commander. При одиночных операциях работает таймер с отсрочкой 1.5 сек. При закрытии Total Commander событие `.NET` `AppDomain.CurrentDomain.ProcessExit` производит финальный ужимающий чекпоинт (`PRAGMA wal_checkpoint(TRUNCATE);`) и полностью очищает пулы подключений `SqliteConnection.ClearAllPools()`.
2. **Защита от лимитов Telegram:** В начале функции `FsPutFile` жестко проверять размер файла (лимит 2 ГБ или 4 ГБ с Premium), чтобы мгновенно блокировать попытку загрузки слишком больших файлов.
3. **Отключение сжатия:** Использовать строго `InputMediaDocument` для любых файлов (включая фото и видео), чтобы Telegram сохранял побитовую копию оригинала без компрессии.
4. **Мгновенный поиск:** Поиск по `Alt+F7` делегируется в SQL-запрос `SELECT * FROM files WHERE name LIKE ...`, что дает огромный прирост скорости по сравнению с локальным диском.
5. **Совместимость API (ANSI / Unicode):** Для поддержки старых версий Total Commander (например, 7.50a) и современных версий с мультиязычными путями, плагин обязан экспортировать как базовые ANSI-функции (`FsFindFirst`, `FsFindNext` и др.), так и их Unicode-аналоги (с суффиксом `W`: `FsFindFirstW`, `FsFindNextW`).
6. **Native AOT & SQLite DLL:** При использовании Native AOT сторонние C-библиотеки не вшиваются в итоговую сборку. Так как плагин загружается в процесс `TOTALCMD.EXE`, пути поиска файлов смещаются. Плагин самостоятельно вычисляет свой реальный путь через `ProcessModule` и принудительно загружает `e_sqlite3.dll` из подпапки `x86/` или `x64/` с помощью `NativeLibrary.Load()` до инициализации базы данных.
7. **Скачивание файлов (FsGetFile / FsGetFileW) и докачка:** 
   - Скачивание медиафайлов из каналов выполняется через низкоуровневый MTProto API `Upload_GetFile` по сохраненному `tg_message_id`.
   - Поддерживается **докачка (Resume)**: скачивание идет во временный файл `<target>.tgpart`. При обрыве или отмене скачивания файл `.tgpart` сохраняется на диске, а при повторном старте скачивание продолжается с уже загруженного байта (с выравниванием по границе чанка `FilePartSize`). Данные не перекачиваются заново с 0 байта, предотвращая порчу и раздувание итогового файла. После 100% скачивания файл атомарно переименовывается в целевое имя.
   - Оптимизация идентичных файлов: если целевой локальный файл уже существует и совпадает по размеру и `MTime` (с допуском до 2 сек), скачивание пропускается и сразу возвращается успех `FS_FILE_OK`.
   - Поддерживается перемещение (F6 / Shift+Drag): при наличии флага `FS_COPYFLAGS_MOVE (4)` в `copyFlags` скачанный файл в Telegram VFS автоматически переносится в виртуальную корзину (`in_trash = 1`), а панель Total Commander обновляется.
   - Сохранение метаданных: после завершения загрузки плагин восстанавливает точную дату изменения файла на диске (`File.SetLastWriteTimeUtc`) в соответствии с `mtime` в Telegram.
    - **Отзывчивый UI-цикл Total Commander и честная Пауза:** Вызывающий поток Total Commander не блокируется монопольно, а выполняет активный цикл ожидания с шагом 50 мс, вызывая `ReportProgress` непосредственно из своего потока. Это обеспечивает немедленный отклик кнопок «Отмена», «Пауза» и закрытия `[X]`. Для физической остановки передачи данных поток записи обернут в `PausableStream`: при паузе в Total Commander шлюз синхронизации (`ManualResetEventSlim`) сбрасывается, блокируя вызовы `Write()` в поток. Это приводит к заполнению TCP-буферов, схлопыванию окна TCP (Zero Window) и полному прекращению сетевого трафика до нажатия «Продолжить» / «Resume».
8. **Загрузка файлов в Telegram (FsPutFile / FsPutFileW) и перемещение (F6):**
   - Выгрузка файлов на серверы Telegram выполняется в фоновом потоке пула через `WTelegramClient.UploadFileAsync` и `InputMediaUploadedDocument`.
   - Исходный локальный файловый поток открывается с флагами `FileShare.ReadWrite | FileShare.Delete` и строго освобождается (`Dispose()`) в блоке `finally` сразу после отправки. Это гарантирует, что локальный файл не блокируется процессом и Total Commander может беспрепятственно удалить его на диске при операции перемещения (F6 / Shift+Drag).
   - Поддерживается флаг `FS_COPYFLAGS_MOVE (4)` в `FsPutFile` для гарантированного удаления исходного файла на диске после успешной выгрузки.
   - Исходный поток оборачивается в `PausableStream(fileStream, pauseGate, cancellationToken)`.
   - Вызывающий поток Total Commander выполняет активный цикл опроса каждые 50 мс с вызовом `ReportProgress(localPath, remotePath, currentPercent)`. Это гарантирует моментальный отклик кнопок **«Отмена»**, **«Пауза»** и **«В фон» (Background)** во время отправки файла.
   - При паузе в Total Commander поток чтения засыпает на шлюзе `pauseGate`, передача данных физически прекращается, а окно диалога продолжает обслуживаться. При отжатии паузы выгрузка продолжается. При нажатии «Отмена» выставляется токен отмены, сетевые сокеты закрываются, и плагин возвращает `FS_FILE_USERABORT`.
   - **Корректная обработка очередей и Синхронизации каталогов:** Опрос `ReportProgress` вызывается исключительно в процессе фактической передачи данных потока (без фиктивных предварительных опросов до запуска сети), что предотвращает залипание статуса отмены в Total Commander при пакетной передаче и в окне «Синхронизация каталогов».
9. **Фоновое копирование, очередь и статусы операций (FsGetBackgroundFlags, FsStatusInfo, FsInitW):**
   - Экспортируются функции `FsGetBackgroundFlags` и `FsGetBackgroundFlagsW`, возвращающие флаги `BG_DOWNLOAD` (1), `BG_UPLOAD` (2) и `BG_ASK_USER` (4).
   - Экспортируются функции `FsStatusInfo` и `FsStatusInfoW` (с обработкой `FS_STATUS_START`/`FS_STATUS_END` и операций `FS_STATUS_OP_GET_MULTI_THREAD`/`FS_STATUS_OP_PUT_MULTI_THREAD`), подтверждающие для Total Commander потокобезопасность плагина.
   - Экспортируется функция `FsInitW` для полной нативной инициализации 64-битного/Unicode Total Commander.
   - Это активирует в Total Commander нативную поддержку фонового копирования и позволяет отправлять операции скачивания и выгрузки в фоновую очередь (F2 / BTM — Background Transfer Manager).
10. **Синхронизация между устройствами через снапшот SQLite (Multi-PC Sync):**
   - Локальная база SQLite (`vfs_cache.db`) выступает единым файлом состояния (снапшотом всей виртуальной файловой системы).
   - После активных изменений на ПК 1 по дебаунсу (или при закрытии) база выгружается в специальный служебный пост Telegram-канала.
   - При открытии канала на ПК 2 плагин сравнивает версию базы и при наличии более свежего снапшота в канале скачивает его, мгновенно получая актуальное дерево файлов без необходимости длительного парсинга тысяч сообщений.
   - Для режима «Зеркало» локальный вотчер сверяет состояние диска с обновленной базой и автоматически докачивает файлы, измененные на другом ПК.
11. **Переименование, перемещение и копирование элементов (FsRenMovFile / FsRenMovFileW):**
    - Вызывается при нажатии клавиш **F5** (Копирование / Drag мышью), **F6** (Перемещение / Переименование / Shift+Drag мышью) в Total Commander.
    - **Соглашение вызовов (ABI WFX):** Экспорты `FsRenMovFile` и `FsRenMovFileW` принимают строго 5 параметров (`OldName`, `NewName`, `MoveFlags`, `OverWrite`, `RemoteInfoStruct*`) с соглашением `stdcall`. Это обеспечивает точное соответствие стека и предотвращает сбои памяти (Access Violation / `c0000005`) в версии Total Commander 7.50a и новее.
    - **Режим перемещения / переименования (MoveFlags != 0 / F6):**
      - *Внутри одного канала:* Выполняется мгновенно на уровне базы SQLite путем обновления полей `name` и `parent` без затрат сетевого трафика.
      - *Между разными каналами:* Выполняется гибридно и безопасно — файл скачивается во временное хранилище, заново выгружается в целевой Telegram-канал (с сохранением структуры папок), запись в SQLite обновляется новым `mount_id` и `tg_message_id`, после чего старое сообщение в исходном Telegram-канале физически удаляется.
    - **Режим виртуального копирования (MoveFlags == 0 / F5):**
      - *Внутри одного канала:* Создает новую запись файла/папки в SQLite с тем же `tg_message_id`. Это происходит **мгновенно** и с **нулевым расходом сетевого трафика**, эмулируя полное копирование.
      - *Между разными каналами:* Скачивает файл и выгружает в целевой Telegram-канал, создавая новую запись в SQLite и **сохраняя** исходное сообщение и запись в исходном канале.
    - **Работа с директориями:** При перемещении и копировании папок каскадно обрабатываются пути для всего дерева подэлементов. Включена защита от циклического копирования/перемещения папки внутрь самой себя. При конфликтах имён с флагом перезаписи `FS_COPYFLAGS_OVERWRITE` вытесняемый элемент перемещается в корзину `[.Trash]`.
12. **Универсальная нормализация виртуальных путей и регистронезависимость (NormalizeVfsPath & COLLATE NOCASE):**
    - Total Commander может передавать пути в томах VFS как в виде `\ChannelName\Subfolder\file.txt`, так и с префиксом имени плагина `\\\tgvfsplugin\ChannelName\Subfolder\file.txt`.
    - Все точки входа WFX (`FsRenMovFile`, `FsPutFile`, `FsGetFile`, `FsDeleteFile`, `FsRemoveDir`, `FsMkDir`, `CreateStateForPath`) используют единую функцию нормализации `NormalizeVfsPath`. Она определяет наличие префикса имени тома/плагина, сверяет сегменты с точками монтирования в SQLite и корректно выделяет название канала и виртуальный подпуть.
    - Все поисковые SQL-запросы к базе SQLite (`GetMountByName`, `GetFile`) выполняются с директивой `COLLATE NOCASE`, что обеспечивает независимость от регистра букв при операциях чтения, записи, переименования и перемещения файлов (F5/F6) в Total Commander.
13. **Открытие, запуск и редактирование файлов (FsExecuteFile / FsExecuteFileW & FsGetFile):**
    - **Запуск по Enter и двойному клику:** Для всех файлов плагин возвращает стандартный код WFX `FS_EXEC_YOURSELF (-1)`. Total Commander автоматически загружает файл во временную системную папку `%TEMP%` и открывает его ассоциированным в Windows приложением (текстовый редактор, плеер, просмотрщик изображений и т.д.).
    - **Встроенный просмотрщик (F3 / Lister):** Total Commander вызывает `FsGetFile` напрямую, файл скачивается и воспроизводится/отображается во встроенном Lister.
    - **Редактирование по F4:** При открытии на редактирование по F4 плагин разрешает скачивание во временный каталог, а после сохранения и закрытия редактора Total Commander автоматически вызывает `FsPutFile`, синхронизируя изменения обратно в Telegram-канал.
    - **Информационное окно свойств по Alt+Enter:** При нажатии `Alt+Enter` на файле или папке плагин перехватывает команду (`verb = "properties"`) и открывает нативный диалог свойств (`FilePropertiesDialog`). В окне отображается подробная информация: имя, виртуальный путь, канал Telegram (с ID канала), размер (в байтах и форматированный), дата изменения, ID сообщения в Telegram (`tg_message_id`), версия/ревизия файла, статус (активный/в корзине) и уникальный UID, а также кнопка быстрого копирования всей информации в буфер обмена.
    - **Служебные элементы корня:** Для виртуальных кнопок `[📁+] Создать папку`, `[❌] Удалить папку`, `[⚙] Настройки` и `[ Login required.txt ]` функция `FsExecuteFile` запускает соответствующие нативные диалоги и возвращает `FS_EXEC_OK (0)`.


## 6. Установка в Total Commander

1. Скачайте `.zip` архив с плагином (например, из раздела Releases в GitHub).
2. Запустите Total Commander.
3. Найдите скачанный архив на одной из панелей, **выделите его курсором и нажмите `Enter`** (или дважды кликните по архиву левой кнопкой мыши).
4. Total Commander автоматически обнаружит конфигурацию и предложит установить плагин — нажмите "ОК"/"Да" на всех этапах.
5. После установки перейдите в **Сетевое окружение** (кнопка `[\]` над панелью или выберите диск "Сеть/FS-плагины") — там появится папка `Telegram VFS`.

## 7. Локальное кэширование и конфигурация (Storage & Settings)
- **Управление расположением данных (Диалог «[*] Настройки плагина»):**
  Пользователь может в любой момент переопределить расположение всех файлов данных плагина (БД, сессия, логи, настройки):
  1. **По умолчанию (%APPDATA%):** `%APPDATA%\TelegramVFS\` — стандартное системное расположение в профиле пользователя.
  2. **Портативный режим (Portable):** подпапка `Data\` прямо рядом с DLL плагина (удобно при запуске Total Commander с флешки). Конфигурация и все файлы (`settings.ini`, `vfs_cache.db`, `WTelegram.session`) хранятся внутри этой подпапки `Data\`.
  3. **Пользовательская папка (Custom):** любой произвольный каталог на локальном или сетевом диске.
- **Единое монолитное хранение файлов:** Все файлы (`vfs_cache.db`, `vfs_cache.db-wal`, `vfs_cache.db-shm`, `WTelegram.session`, `settings.ini`, `plugin_log.txt`) всегда хранятся вместе внутри активной папки данных. Корень плагина не захламляется дублирующими файлами.
- **Автоматический перенос файлов (Data Migration):** При смене расположения в диалоге настроек плагин автоматически перемещает существующие файлы (включая `settings.ini` со всеми ключами API и телефоном) в новую директорию без потери авторизации и истории.
- **Бесшовный перезапуск (Hot Reload):** При сохранении настроек плагин освобождает дескрипторы базы данных (`SqliteConnection.ClearAllPools()`) и сессии Telegram, обновляет пути и лениво переподключается при следующем обращении к любой виртуальной папке.
- **Локальная БД:** Все данные о каналах, чатах, папках и файлах кэшируются в локальной базе данных SQLite (`vfs_cache.db`).
- **Сессия:** Библиотека `WTelegramClient` сохраняет ключи сессии в файл `WTelegram.session` в выбранной папке данных, обеспечивая постоянную авторизацию.
- **Настройки (settings.ini):** Конфигурация плагина хранится в INI-файле (`storage_mode`, `data_path`, `api_id`, `api_hash`, `phone_number`).
- **Логирование (`plugin_log.txt`):** Вся работа плагина подробно и структурированно фиксируется в `plugin_log.txt` в активной папке данных:
  - **Формат записи:** `[HH:mm:ss.fff] [LEVEL] [TAG] [L/R] Message`
  - **Префикс панели:** `[L]` (левая панель) или `[R]` (правая панель) — определяется через Win32 API по координатам фокуса ввода и кэшируется на 100 мс для исключения накладных расходов.
  - **Уровни:** `[INFO]`, `[WARN]`, `[ERROR]`, `[DEBUG]`. При возникновении исключений ошибки записываются с полным стек-трейсом.
  - **Категории (Теги):**
    - `[WFX]` — операции файловой системы Total Commander (загрузка, выгрузка, переименование, удаление, отмена/пауза передачи).
    - `[TG]` — сетевые вызовы и события Telegram API (авторизация, создание каналов, постинг/скачивание сообщений и чанков).
    - `[DB]` — транзакции и операции SQLite (запись версий файлов, перемещение в корзину, WAL чекпоинты).
    - `[CFG]` — чтение, сохранение и миграция настроек хранилища и ключей API.
    - `[UI]` — открытие и действия в диалоговых окнах плагина.
    - `[WIN32]` — взаимодействие с окнами и контролами Total Commander через Win32 API.
  - **Человекочитаемые размеры:** Размеры файлов в логах форматируются автоматически (`B`, `KB`, `MB`, `GB`).
  - **Потокобезопасность:** Запись в файл лога защищена синхронизацией потоков (`lock`) с автоматической ротацией при превышении размера 10 МБ.

## 8. Стандарты UI/UX и Интеграция с TC
Поскольку плагин работает внутри Total Commander и использует нативные формы Windows (WinForms) для диалогов, мы придерживаемся следующих правил:
- **Шрифт:** Все формы и контролы должны использовать современный шрифт `Segoe UI` размером `9pt` (`Font = new Font("Segoe UI", 9)`).
- **Высота кнопок (Buttons):** Из-за использования нестандартного шрифта автоматический размер кнопок в WinForms может искажаться (сплющиваться). Для всех кнопок в диалоговых окнах (OK, Отмена и т.д.) должна жестко задаваться высота: `Height = 30`.
- **Обновление панелей (RefreshActivePanel):** Окно Total Commander не должно обновляться "просто так" по таймеру или в фоне, так как это вызывает визуальные мерцания и сбивает выделение файлов. Метод `Win32Api.RefreshActivePanel()` (запускающий асинхронную задержку в 100мс перед отправкой сообщения `cm_RereadSource`) должен вызываться **исключительно** как финальный этап успешно завершенной пользовательской операции: авторизации, создания папки/канала, переименования, удаления или загрузки файла.

## 9. Пользовательские колонки и подсказки (WFX Content Plugin API)
Плагин реализует официальный интерфейс Total Commander Content Plugin (WDX в составе WFX) для отображения метаданных файлов во всплывающих подсказках (Tooltips) и настраиваемых колонках (Custom Columns View):

* **Экспортируемые функции:**
  * `FsContentGetSupportedField` / `FsContentGetSupportedFieldW` — перечисление доступных полей плагина.
  * `FsContentGetSupportedFieldFlags` — флаги полей (`CONTFLAGS_OPTIONAL`).
  * `FsContentGetDefaultSortOrder` — порядок сортировки по умолчанию.
  * `FsContentGetValue` / `FsContentGetValueW` — получение значения поля для конкретного элемента в VFS.
  * `FsContentGetDefaultView` / `FsContentGetDefaultViewW` — схема колонок по умолчанию (`Версия`, `Размер`, `Дата`).
  * `FsContentPluginUnload` — выгрузка плагина.

* **Поддерживаемые поля плагина (системный префикс `<fs>` в Total Commander):**
  * `Version` (`FT_NUMERIC_32`, поле `[=<fs>.Version]`) — числовая версия файла (1, 2, 3...) для удобной сортировки и числовых фильтров.
  * `VersionName` (`FT_STRINGW`, поле `[=<fs>.VersionName]`) — строковое обозначение версии файла (например, `v1`, `v2`, `v3`).
  * `FileName` (`FT_STRINGW`, поле `[=<fs>.FileName]`) — оригинальное чистое имя файла без суффиксов версий.
  * `TgMessageId` (`FT_NUMERIC_32`, поле `[=<fs>.TgMessageId]`) — ID соответствующего сообщения с файлом в Telegram-канале.

* **Производительность и локальный кэш:** Все значения полей извлекаются мгновенно из локальной базы SQLite (`VfsDatabase`) по индексам `idx_files_mount_parent` без отправки сетевых запросов в Telegram API.

* **Настройка в Total Commander:**
  * **Всплывающие подсказки (Tooltips):** в `Конфигурация -> Экран -> Подсказки -> Пользовательские подсказки (+)` для типа `*.*` указывается шаблон:
    ```
    Имя: [=<fs>.FileName]
    Версия: [=<fs>.VersionName]
    Размер: [=tc.размер]
    Дата: [=tc.дата записи]
    ID сообщения TG: #[=<fs>.TgMessageId]
    ```
    При наведении курсора мыши на файл в панели Total Commander отображает всплывающую подсказку с оригинальным именем и версией файла.
  * **Пользовательские колонки (Custom Columns):** в `Вид -> Наборы колонок -> Настройка колонок` можно выбрать предустановленный вид колонок плагина (со столбцами `Версия`, `Размер`, `Дата`) или добавить колонку с полем `[=<fs>.VersionName]`. При создании/редактировании набора колонок имя «стандартный» можно переименовать в любое удобное (например, «Telegram VFS») прямо в текстовом поле «Имя» и сохранить по нажатию дискеты 💾.

### 10. Умная синхронизация по источникам (Smart Sync & Origin Tracking)
Специальный механизм для режима **«Контейнер» (Виртуальные подборки / Плейлисты / Сборники документов)**, когда файлы в Telegram собраны из разных папок и дисков ПК (например, новогодний плейлист `НГ/музыка` собран из треков в `D:\Music\ABBA\...`, `E:\Downloads\...`, или годовые отчеты собраны в один каталог из `D:\Reports\2010\..`, `D:\Reports\2011\..`):

* **Фиксация источника (`source_path`):**
  * При выгрузке любого файла в плагин (`FsPutFile`) плагин сохраняет в SQLite полный локальный путь файла-источника (`localName`).
  * При переименовании или перемещении внутри виртуальной файловой системы (`FsRenMovFile`) путь к источнику бережно сохраняется.
  * **Защита при редактировании через Total Commander (F4):** когда файл редактируется через F4, Total Commander скачивает его во временный каталог (`%TEMP%\_tc\...`) и затем сохраняет через `FsPutFile`. Плагин автоматически определяет временные файлы (`_tc` / `%TEMP%`) и не перезаписывает оригинальный `source_path` на диске мусорным временным путем, сохраняя исходную привязку файла.
* **Интеграция с UI и свойствами (`Alt+Enter`):**
  * **Контекстное открытие для текущей папки / канала через пункт «`..`»:** Нажатие `Alt+Enter` (или контекстное меню -> «Свойства») на верхнем элементе возврата `..` в файловой панели Total Commander мгновенно открывает окно свойств текущей открытой папки (или корня канала/корзины), позволяя запускать Smart Sync, переходить в корзину и смотреть статистику текущей директории прямо изнутри неё без необходимости подниматься на уровень выше.
  * В окне свойств файла (`FilePropertiesDialog`) отображается блок **«Локальный источник на ПК»** с полным путем к оригиналу.
  * Кнопка **«Найти на ПК»** — мгновенно открывает проводник / папку с файлом в Total Commander.
  * Кнопка **«Синхронизировать»** — проверяет статус конкретного файла (сравнивает размер и mtime локального файла и версии в Telegram).
* **Пакетная синхронизация контейнера (Smart Sync Scan):**
  * Запуск сканирования для всей папки/контейнера со сбором статусов:
    * 🟢 **На ПК новее** (файл на диске обновлен, лучшее качество / свежая редакция) ➔ Рекомендация: *Обновить в Telegram* (предыдущая версия автоматически уходит в виртуальную корзину `_v1`).
    * 🔵 **В Telegram новее** (документ отредактирован в облаке) ➔ Рекомендация: *Обновить на ПК*.
    * ⚪ **Идентичны** (размер и дата совпадают с допуском ±2 сек) ➔ Пропуск.
    * 🟠 **Разный размер** (даты изменения совпадают с точностью до 2 сек, но размер файлов отличается) ➔ Предупреждение / *Требует решения* (чекбокс снят по умолчанию для защиты от случайной перезаписи данных).
    * 🔴 **Источник отсутствует** (локальный файл удален или диск недоступен) ➔ Предупреждение (файл продолжает безопасно храниться в облаке Telegram без риска случайного удаления).
    * **Сетка колонок в стиле классической синхронизации Total Commander (7 колонок):**
      * Таблица сопоставления версий построена по стандарту окна «Синхронизация каталогов» Total Commander:
        1. `Путь в VFS` (виртуальный путь файла с пометкой `🏷️`, если файл был переименован).
        2. `Размер (TG)` (размер файла в Telegram в байтах с разделителями тысяч и выравниванием вправо).
        3. `Дата (TG)` (дата модификации файла в Telegram).
        4. `<=>` (символ направления: `-->>` на ПК новее, `<<--` в TG новее, `=` идентичны, `≠` конфликт размеров, `❌` не найден на диске).
        5. `Дата (ПК)` (дата модификации файла на диске ПК).
        6. `Размер (ПК)` (размер файла на диске ПК в байтах с разделителями тысяч и выравниванием вправо).
        7. `Оригинал на ПК` (полный локальный путь к исходному файлу на диске).
      * **Интерактивные подробные подсказки (ToolTips) по всей строке:** при наведении курсора мыши на любую ячейку строки (направление, размер, статус или путь) всплывает подробная сводка с точным сравнением дат, размеров обеих копий и расчетом времени опережения (например, *«Файл на ПК новее на 2 дн. 19 ч.»* или *«🏷️ Файл переименован в VFS (на ПК: old_name.txt)»*).
      * **Визуальное, фоновое и шрифтовое выделение строк:** 
        * Строки с изменениями подсвечиваются мягкими статусными фонами и жирным шрифтом (`Bold`):
          * `На ПК новее -->>` — мягкий пастельный светло-зеленый фон (`#EBF8EB`) с темно-зеленым шрифтом и указателем `-->>`.
          * `В TG новее <<--` — мягкий пастельный светло-голубой фон (`#EBF4FF`) с темно-синим шрифтом и указателем `<<--`.
          * `Разный размер ≠` — мягкий янтарно-песочный фон (`#FFF7E6`) с темно-оранжевым шрифтом.
          * `Не найден ❌` — мягкий светло-розовый фон (`#FFEBEB`) с темно-красным шрифтом.
        * Неизмененные файлы (`=`) отображаются серым регулярным шрифтом с деликатной «зеброй» (белый / едва заметный серый `#F8F9FA`) для максимального комфорта при чтении длинных списков.
      * **Адаптивный интерфейс и сохранение геометрии (settings.ini):**
        * Диалог Smart Sync поддерживает свободное изменение размеров (`Sizable`), разворачивание на весь экран (`MaximizeBox`) и устранение мерцания перерисовки (`DoubleBuffered`).
        * При закрытии окна плагин автоматически сохраняет ширины всех 7 колонок, состояние разворачивания и размеры окна в `settings.ini`, сохраняя удобные пропорции при повторных открытиях и на мониторах любого разрешения (от FullHD до 4K).
* **Пользовательские колонки и всплывающие подсказки:**
  * Дополнительное WFX Content-поле `[=<fs>.SourcePath]` для отображения пути оригинального файла на ПК прямо в колонках панели Total Commander и всплывающих подсказках.

## 11. Система правил исключения файлов (.tgignore)
Механизм гибкой фильтрации и защиты конфиденциальных или служебных файлов от случайной выгрузки в Telegram при зеркалировании, синхронизации каталогов или пакетном копировании (F5 / Drag-and-Drop):

* **Единый файл правил `.tgignore`:**
  * Располагается в рабочей папке данных плагина (рядом с `vfs.db` и `vfs_settings.json` — по умолчанию в `%APPDATA%\GHISLER\TelegramVfs\.tgignore` или в подпапке `Data\` в портативном режиме).
  * Локальные рабочие папки пользователя на диске остаются чистыми от служебных файлов плагина.
  * Редактирование доступно в любом текстовом редакторе (Блокнот, Notepad++, VS Code), а также по кнопке **«Исключения (.tgignore)...»** прямо в окне настроек плагина (`SettingsDialog`). При первом открытии плагин автоматически создает заготовку с подробными комментариями и популярными шаблонами.

* **Поддерживаемый синтаксис (стандарт gitignore):**
  * Строки с решеткой `#` — комментарии.
  * Маски имен файлов: `пароли.txt`, `id_rsa`, `*.kdbx`, `*.key`.
  * Системный и временный мусор ОС: `desktop.ini`, `Thumbs.db`, `~$*`, `.DS_Store`.
  * Конкретные относительные пути: `Документы/разное/не удалять/пароли.txt`.
  * Игнорирование каталогов и поддеревьев: `*/node_modules/*`, `*/.git/*`, `*/temp/*`, `разное/не удалять/`.
  * Инверсия правил (исключение из игнорирования через восклицательный знак `!`): `!важные_пароли.txt`.

* **Логика работы и перехват (`FsPutFile`):**
  * Правила компилируются и кэшируются в памяти с отслеживанием даты изменения файла `.tgignore`, обеспечивая микросекундную скорость сопоставления путей без замедления файловых операций.
  * При попытке передачи файла в плагин (`FsPutFile`), если целевой относительный путь или имя файла совпадает с правилом исключения:
    * Загрузка в сеть Telegram немедленно прерывается (трафик не расходуется, конфиденциальные данные не покидают ПК).
    * В лог записывается событие: `[IGNORE] File '{path}' matches .tgignore rule '{rule}', upload skipped`.
    * Плагин возвращает штатный успешный код `FS_FILE_OK`, что позволяет пакетным операциям Total Commander продолжать выгрузку остальных нужных файлов папки без прерываний и раздражающих окон ошибок.
  * В диалоге умной синхронизации (`SmartSyncDialog`) файлы, подпадающие под маски `.tgignore`, автоматически помечаются серым статусом `[Игнорируется (.tgignore)]` и исключаются из списка выгрузки.

## 12. Единый нативный интерфейс диалоговых окон (UI Theme & Design Guidelines)
Все диалоговые окна плагина (`SmartSyncDialog`, `FilePropertiesDialog`, `SettingsDialog`, `CreateFolderDialog`, `DeleteFolderDialog`, `InputDialog`) приведены к единому нативному визуальному стандарту Total Commander и Windows через унифицированный хелпер `UiTheme.cs`:

* **Единые стандарты высоты и контролов:**
  - Все кнопки (`Button`), поля ввода (`TextBox`) и выпадающие списки (`ComboBox`) имеют строгую фиксированную высоту **30 px** (`UiTheme.DefaultButtonHeight` / `UiTheme.DefaultInputHeight`).
  - Для всех текстовых полей и списков гарантирован отклик и единообразие за счет фабричных методов:
    - `UiTheme.CreateButton(...)` — кнопки с `TextAlign = ContentAlignment.MiddleCenter` и динамической шириной.
    - `UiTheme.CreateTextBox(...)` — поля ввода с отключенным `AutoSize` и высотой 30px.
    - `UiTheme.CreateComboBox(...)` — списки со стилем `DropDownList` и высотой 30px.
    - `UiTheme.CreateDialogForm(...)` — стандартизированные формы с `AutoScaleMode = AutoScaleMode.None`.
* **Типографика и шрифты:**
  * Основной шрифт всех элементов интерфейса: `Segoe UI`, 9pt (`UiTheme.DefaultFont`).
  * Заголовки разделов и окон: `Segoe UI`, 11pt Bold (`UiTheme.HeaderTitleFont`).
  * Акцентные метки и значения параметров: `Segoe UI`, 9pt Bold (`UiTheme.BoldFont`).
* **Геометрия и сетка диалогов:**
  * Боковые отступы (`margin`): **20 px**.
  * Верхний отступ (`topMargin`): **16 px**.
  * Нижний отступ до нижней панели: **16 px**.
  * Высота нижней панели действий (`UiTheme.CreateBottomPanel`): **52 px** с размещением кнопок `Top = 11` px (центрирование по вертикали).
* **Нижняя панель действий (`UiTheme.CreateBottomPanel`):**
  * Панель футера со стандартной высотой (52px), фоном `Color.FromArgb(245, 247, 250)` и тонкой линией-разделителем сверху (`Color.FromArgb(220, 224, 230)`).
  * Кнопки первичных и специальных действий (например, «Выбрать разные», «Снять выбор», «Smart Sync», «Очистить») выравниваются по левому краю (`Anchor = Top | Left`).
  * Кнопки подтверждения и закрытия («OK», «Синхронизировать», «Сохранить», «Отмена», «Закрыть») группируются по правому краю (`Anchor = Top | Right`).
* **Геометрия и адаптивность:**
  * Установка строгого `MinimumSize` для всех форм во избежание наложения или скрытия элементов при сжатии окна.
  * Блокировка мерцания через `DoubleBuffered` и правильная модальная блокировка главного окна Total Commander через `ShowModalTc()`.
