# Telegram VFS Plugin (Total Commander)

Архитектурный концепт WFX-плагина для Total Commander, позволяющего работать с личным Telegram-каналом как с виртуальной файловой системой (VFS).

## 1. Ядро и технологии
* **Язык/Платформа:** C# (.NET 9+).
* **Библиотека Telegram:** `WTelegramClient` (MTProto API).
* **Формат сборки:** Нативная DLL для Windows через **Native AOT** (не требует установки .NET Framework у пользователя).
* **Сборка и CI/CD:** Компиляция и версионирование осуществляются автоматически через **GitHub Actions**. Итоговые артефакты (готовые `.zip` архивы с плагинами `.wfx` и `.wfx64`) публикуются в GitHub Releases.

## 2. Локальный движок (SQLite)
Для обеспечения нулевой задержки (0 мс) при навигации используется локальная база данных SQLite.
* **Структура БД (Adjacency List):**
  * `uid` (уникальный идентификатор)
  * `isdir` (папка или файл)
  * `name` (имя файла/папки)
  * `parent` (uid родительской папки, либо false/null для корня)
  * `mtime` (дата модификации)
  * `size` (размер файла)
  * `tg_message_id` (ID сообщения в Telegram)
  * `in_trash` (флаг удаления, boolean)
  * `ver` (версия файла)

## 3. Хранилище и Синхронизация
* **Формат хранилища:** Приватный Telegram-канал (назовем его `TGvfs`). **Каналы предпочтительнее групп**, так как в них нет системных сообщений о вступлении/выходе, и они идеально подходят для однонаправленного потока данных.
* **Авторизация и 2FA:** Сессия пользователя сохраняется локально в `.session` файл (в `%APPDATA%\TelegramVFS`), который поддерживается библиотекой WTelegramClient. Поддерживается полная цепочка входа: Номер телефона -> Код из Telegram -> 2FA пароль (если установлен).
* **Инициализация (Первый запуск):** 
  1. После логина плагин ищет приватный канал с именем `TGvfs` среди диалогов пользователя.
  2. Если канала нет, плагин автоматически создает его.
  3. Плагин формирует начальную базу `vfs_cache.db`, загружает её в канал и **закрепляет** (Pin) это сообщение.
* **Синхронизация на новых устройствах:** При логине с другого ПК плагин находит существующий канал `TGvfs`, скачивает закрепленное сообщение (актуальную базу) и мгновенно восстанавливает всю структуру VFS без сканирования истории.
* **Бекап базы (Debounce):** При изменении структуры (создание, переименование, удаление) плагин ждет "тишины" (например, 3 минуты). Если изменений больше нет — тихо загружает новую версию базы в канал и обновляет закрепление.

## 4. Механики безопасности и отказоустойчивости
* **Страховочные подписи (Captions):** При загрузке файла в Telegram, в подпись (caption) сообщения записывается относительный путь (например, `docs/2026/info.txt`). Это позволит написать скрипт-восстановитель, если SQLite-база будет безвозвратно утеряна.
* **Виртуальная корзина `[.Trash]`:** При удалении (F8) или перезаписи файла, сообщение в Telegram не удаляется. В SQLite старая запись помечается `in_trash = true` и переносится в виртуальную папку корзины. Физическое удаление из Telegram происходит только при удалении файла из корзины.
* **Сборщик мусора (Temp):** Скачанные для предпросмотра (F3) файлы падают в `%TEMP%/TgPluginCache`. При старте плагин очищает кэш от файлов старше 7 дней или если общий объем превышает 5 ГБ.

## 5. Важные технические нюансы реализации
1. **Режим WAL для SQLite:** Обязательно включить `PRAGMA journal_mode=WAL;`, чтобы фоновое копирование (BTM) не блокировало базу и интерфейс TC при параллельной навигации.
2. **Защита от лимитов Telegram:** В начале функции `FsPutFile` жестко проверять размер файла (лимит 2 ГБ или 4 ГБ с Premium), чтобы мгновенно блокировать попытку загрузки слишком больших файлов.
3. **Отключение сжатия:** Использовать строго `InputMediaDocument` для любых файлов (включая фото и видео), чтобы Telegram сохранял побитовую копию оригинала без компрессии.
4. **Мгновенный поиск:** Поиск по `Alt+F7` делегируется в SQL-запрос `SELECT * FROM files WHERE name LIKE ...`, что дает огромный прирост скорости по сравнению с локальным диском.
5. **Совместимость API (ANSI / Unicode):** Для поддержки старых версий Total Commander (например, 7.50a) и современных версий с мультиязычными путями, плагин обязан экспортировать как базовые ANSI-функции (`FsFindFirst`, `FsFindNext` и др.), так и их Unicode-аналоги (с суффиксом `W`: `FsFindFirstW`, `FsFindNextW`).
6. **Native AOT & SQLite DLL:** При использовании Native AOT сторонние C-библиотеки не вшиваются в итоговую сборку. Так как плагин загружается в процесс `TOTALCMD.EXE`, пути поиска файлов смещаются. Плагин самостоятельно вычисляет свой реальный путь через `ProcessModule` и принудительно загружает `e_sqlite3.dll` из подпапки `x86/` или `x64/` с помощью `NativeLibrary.Load()` до инициализации базы данных.

## 6. Установка в Total Commander

1. Скачайте `.zip` архив с плагином (например, из раздела Releases в GitHub).
2. Запустите Total Commander.
3. Найдите скачанный архив на одной из панелей, **выделите его курсором и нажмите `Enter`** (или дважды кликните по архиву левой кнопкой мыши).
4. Total Commander автоматически обнаружит конфигурацию и предложит установить плагин — нажмите "ОК"/"Да" на всех этапах.
5. После установки перейдите в **Сетевое окружение** (кнопка `[\]` над панелью или выберите диск "Сеть/FS-плагины") — там появится папка `Telegram VFS`.
