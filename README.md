# Telegram VFS Plugin (Total Commander)

Архитектурный концепт WFX-плагина для Total Commander, позволяющего работать с личным Telegram-каналом как с виртуальной файловой системой (VFS).

## 1. Ядро и технологии
* **Язык/Платформа:** C# (.NET 9+).
* **Библиотека Telegram:** `WTelegramClient` (MTProto API).
* **Формат сборки:** Нативная DLL для Windows через **Native AOT** (не требует установки .NET Framework у пользователя).
* **Сборка и CI/CD:** Компиляция и версионирование осуществляются автоматически через **GitHub Actions**. Итоговые артефакты (готовые `.zip` архивы с плагинами `.wfx` и `.wfx64`) публикуются в GitHub Releases.

## 2. Локальный движок (SQLite)
Для обеспечения нулевой задержки (0 мс) при навигации используется локальная база данных SQLite. Плагин оперирует множеством подключений, каждое из которых соответствует отдельному Telegram-каналу.

* **Таблица `mounts` (Точки монтирования / Каналы):**
  * `id` (уникальный идентификатор, например `tg-fldr-123`)
  * `local_path` (привязанный локальный путь на ПК, для режима Зеркало)
  * `channel_id` (ID приватного канала в Telegram)
  * `channel_name` (название папки/канала)
  * `mode` (Режим работы: `0` - Зеркало, `1` - Контейнер)
  * `created_at` (дата создания, Unix Timestamp в миллисекундах, INTEGER)

* **Таблица `files` (Структура файлов и папок - Adjacency List):**
  * `uid` (уникальный идентификатор файла/папки)
  * `mount_id` (ID точки монтирования из таблицы `mounts`)
  * `isdir` (папка или файл)
  * `name` (имя файла/папки)
  * `parent` (относительный путь к родительской папке, например `docs/2026`, либо null/''/false для корня канала)
  * `mtime` (дата модификации, Unix Timestamp в миллисекундах, INTEGER)
  * `size` (размер файла)
  * `tg_message_id` (ID сообщения в Telegram)
  * `in_trash` (флаг удаления, boolean)
  * `ver` (версия файла)
  * Индекс `idx_files_mount_parent` по полях `(mount_id, parent, in_trash)` для мгновенного выполнения иерархических запросов.

## 3. Режимы работы и Управление каналами
* **Менеджер подключений (Корень плагина):** В корневой директории плагина (`\\tgvfsplugin\`) не хранятся файлы. Там находятся:
  * Служебный триггер `[📁+] Создать папку` — при клике открывается диалог с вводом имени и переключателем режима (Зеркало/Контейнер).
  * Служебный триггер `[❌] Удалить папку` — при клике открывается диалог выбора виртуальной папки, после чего выводится дополнительное окно подтверждения с явным предупреждением о том, что удаление также физически удалит канал и все файлы в Telegram. При подтверждении канал удаляется в Telegram через API WTelegramClient (`Channels_DeleteChannel`), а папка отмонтируется из базы SQLite.
  * Служебный триггер `[⚙] Настройки` — при клике открывается окно конфигурации.
  * Список уже подключенных папок. На каждой такой папке также поддерживается нативное удаление по клавише `F8` / `Delete` в Total Commander через функцию `FsRemoveDir` (с вызовом окна предупреждения и удалением канала).
* **Режим "Зеркало" (Бэкап):** Жестко привязывается к локальной папке на ПК (сохраняется в `local_path`). При входе в Зеркало в плагине, соседняя панель Total Commander автоматически переключается на `local_path`. Плагин динамически определяет позицию фокуса относительно центра окна Total Commander через Win32 API (`GetGUIThreadInfo`, `GetWindowRect`) и отправляет сообщение `WM_COPYDATA` с разделителем `\r`, гарантированно открывая директорию в противоположной неактивной панели (независимо от того, открыт плагин в левой или правой панели). Идеально для использования штатной функции TC "Синхронизировать каталоги".
* **Режим "Контейнер" (Флешка):** Обычная виртуальная папка без привязки к локальному пути. Соседняя панель при навигации не затрагивается.
* **Хранилище в Telegram:** Каждая созданная папка создает **отдельный приватный канал** в Telegram. Для порядка в мессенджере каналам автоматически добавляется префикс `[TC]` (например, `[TC] MyBackup`), который скрывается при отображении в Total Commander.
* **Авторизация и 2FA:** Сессия пользователя сохраняется локально в `.session` файл (в `%APPDATA%\TelegramVFS`). Поддерживается полная цепочка входа: Номер телефона -> Код из Telegram -> 2FA пароль.
* **Метаданные (База в канале):** В каждый созданный канал плагин загружает слепок SQLite-базы, относящийся только к этому каналу, и закрепляет (Pin) сообщение. На другом ПК при входе плагин считывает эти закрепленные сообщения и мгновенно восстанавливает структуру всех зеркал и контейнеров.

## 4. Механики безопасности и отказоустойчивости
* **Страховочные подписи (Captions):** При загрузке файла в Telegram, в подпись (caption) сообщения записывается относительный путь (например, `docs/2026/info.txt`). Это позволит написать скрипт-восстановитель, если SQLite-база будет безвозвратно утеряна.
* **Виртуальная корзина `[.Trash]`:** При удалении (F8) или перезаписи файла, сообщение в Telegram не удаляется. В SQLite старая запись помечается `in_trash = true` и переносится в виртуальную папку корзины. Физическое удаление из Telegram происходит только при удалении файла из корзины.
* **Сборщик мусора (Temp):** Скачанные для предпросмотра (F3) файлы падают в `%TEMP%/TgPluginCache`. При старте плагин очищает кэш от файлов старше 7 дней или если общий объем превышает 5 ГБ.

## 5. Важные технические нюансы реализации
1. **Режим WAL для SQLite и умный сброс (Batch Checkpoint):** Включен `PRAGMA journal_mode=WAL;`, чтобы фоновое копирование (BTM) не блокировало базу и интерфейс TC при параллельной навигации. Реализована система умного сброса `TriggerCheckpoint`: при пакетных операциях (выгрузка списка из N файлов) одиночные сбросы пропускаются, и выполняет 1 неблокирующий чекпоинт (`PRAGMA wal_checkpoint(PASSIVE);`) по событию `FS_STATUS_END` от Total Commander. При одиночных операциях работает таймер с отсрочкой 1.5 сек. При закрытии Total Commander событие `.NET` `AppDomain.CurrentDomain.ProcessExit` производит финальный ужимающий чекпоинт (`PRAGMA wal_checkpoint(TRUNCATE);`) и полностью очищает пулы подключений `SqliteConnection.ClearAllPools()`.
2. **Защита от лимитов Telegram:** В начале функции `FsPutFile` жестко проверять размер файла (лимит 2 ГБ или 4 ГБ с Premium), чтобы мгновенно блокировать попытку загрузки слишком больших файлов.
3. **Отключение сжатия:** Использовать строго `InputMediaDocument` для любых файлов (включая фото и видео), чтобы Telegram сохранял побитовую копию оригинала без компрессии.
4. **Мгновенный поиск:** Поиск по `Alt+F7` делегируется в SQL-запрос `SELECT * FROM files WHERE name LIKE ...`, что дает огромный прирост скорости по сравнению с локальным диском.
5. **Совместимость API (ANSI / Unicode):** Для поддержки старых версий Total Commander (например, 7.50a) и современных версий с мультиязычными путями, плагин обязан экспортировать как базовые ANSI-функции (`FsFindFirst`, `FsFindNext` и др.), так и их Unicode-аналоги (с суффиксом `W`: `FsFindFirstW`, `FsFindNextW`).
6. **Native AOT & SQLite DLL:** При использовании Native AOT сторонние C-библиотеки не вшиваются в итоговую сборку. Так как плагин загружается в процесс `TOTALCMD.EXE`, пути поиска файлов смещаются. Плагин самостоятельно вычисляет свой реальный путь через `ProcessModule` и принудительно загружает `e_sqlite3.dll` из подпапки `x86/` или `x64/` с помощью `NativeLibrary.Load()` до инициализации базы данных.
7. **Скачивание файлов (FsGetFile / FsGetFileW) и докачка:** 
   - Скачивание медиафайлов из каналов выполняется через низкоуровневый MTProto API `Upload_GetFile` по сохраненному `tg_message_id`.
   - Поддерживается **докачка (Resume)**: скачивание идет во временный файл `<target>.tgpart`. При обрыве или отмене скачивания файл `.tgpart` сохраняется на диске, а при повторном старте скачивание продолжается с уже загруженного байта (с выравниванием по границе чанка `FilePartSize`). Данные не перекачиваются заново с 0 байта, предотвращая порчу и раздувание итогового файла. После 100% скачивания файл атомарно переименовывается в целевое имя.
   - Оптимизация идентичных файлов: если целевой локальный файл уже существует и совпадает по размеру и `MTime` (с допуском до 2 сек), скачивание пропускается и сразу возвращается успех `FS_FILE_OK`.
   - Поддерживается перемещение (F6 / Shift+Drag): при наличии флага `FS_COPYFLAGS_MOVE (4)` в `copyFlags` скачанный файл в Telegram VFS автоматически переносится в виртуальную корзину (`in_trash = 1`), а панель Total Commander обновляется.
   - Сохранение метаданных: после завершения загрузки плагин восстанавливает точную дату изменения файла на диске (`File.SetLastWriteTimeUtc`) в соответствии с `mtime` в Telegram.
    - **Отзывчивый UI-цикл Total Commander и честная Пауза:** Вызывающий поток Total Commander не блокируется монопольно, а выполняет активный цикл ожидания с шагом 50 мс, вызывая `ReportProgress` непосредственно из своего потока. Это обеспечивает немедленный отклик кнопок «Отмена», «Пауза» и закрытия `[X]`. Для физической остановки передачи данных поток записи обернут в `PausableStream`: при паузе в Total Commander шлюз синхронизации (`ManualResetEventSlim`) сбрасывается, блокируя вызовы `Write()` в поток. Это приводит к заполнению TCP-буферов, схлопыванию окна TCP (Zero Window) и полному прекращению сетевого трафика до нажатия «Продолжить» / «Resume».
8. **Загрузка файлов в Telegram (FsPutFile / FsPutFileW) и перемещение (F6):**
   - Выгрузка файлов на серверы Telegram выполняется в фоновом потоке пула через `WTelegramClient.UploadFileAsync` и `InputMediaUploadedDocument`.
   - Исходный локальный файловый поток открывается с флагами `FileShare.ReadWrite | FileShare.Delete` и строго освобождается (`Dispose()`) в блоке `finally` сразу после отправки. Это гарантирует, что локальный файл не блокируется процессом и Total Commander может беспрепятственно удалить его на диске при операции перемещения (F6 / Shift+Drag).
   - Поддерживается флаг `FS_COPYFLAGS_MOVE (4)` в `FsPutFile` для гарантированного удаления исходного файла на диске после успешной выгрузки.
   - Исходный поток оборачивается в `PausableStream(fileStream, pauseGate, cancellationToken)`.
   - Вызывающий поток Total Commander выполняет активный цикл опроса каждые 50 мс с вызовом `ReportProgress(localPath, remotePath, currentPercent)`. Это гарантирует моментальный отклик кнопок **«Отмена»**, **«Пауза»** и **«В фон» (Background)** во время отправки файла.
   - При паузе в Total Commander поток чтения засыпает на шлюзе `pauseGate`, передача данных физически прекращается, а окно диалога продолжает обслуживаться. При отжатии паузы выгрузка продолжается. При нажатии «Отмена» выставляется токен отмены, сетевые сокеты закрываются, и плагин возвращает `FS_FILE_USERABORT`.
9. **Фоновое копирование, очередь и статусы операций (FsGetBackgroundFlags, FsStatusInfo, FsInitW):**
   - Экспортируются функции `FsGetBackgroundFlags` и `FsGetBackgroundFlagsW`, возвращающие флаги `BG_DOWNLOAD` (1), `BG_UPLOAD` (2) и `BG_ASK_USER` (4).
   - Экспортируются функции `FsStatusInfo` и `FsStatusInfoW` (с обработкой `FS_STATUS_START`/`FS_STATUS_END` и операций `FS_STATUS_OP_GET_MULTI_THREAD`/`FS_STATUS_OP_PUT_MULTI_THREAD`), подтверждающие для Total Commander потокобезопасность плагина.
   - Экспортируется функция `FsInitW` для полной нативной инициализации 64-битного/Unicode Total Commander.
   - Это активирует в Total Commander нативную поддержку фонового копирования и позволяет отправлять операции скачивания и выгрузки в фоновую очередь (F2 / BTM — Background Transfer Manager).
10. **Синхронизация между устройствами через снапшот SQLite (Multi-PC Sync):**
   - Локальная база SQLite (`vfs_cache.db`) выступает единым файлом состояния (снапшотом всей виртуальной файловой системы).
   - После активных изменений на ПК 1 по дебаунсу (или при закрытии) база выгружается в специальный служебный пост Telegram-канала.
   - При открытии канала на ПК 2 плагин сравнивает версию базы и при наличии более свежего снапшота в канале скачивает его, мгновенно получая актуальное дерево файлов без необходимости длительного парсинга тысяч сообщений.
   - Для режима «Зеркало» локальный вотчер сверяет состояние диска с обновленной базой и автоматически докачивает файлы, измененные на другом ПК.
11. **Переименование, перемещение и копирование элементов (FsRenMovFile / FsRenMovFileW):**
    - Вызывается при нажатии клавиш **F5** (Копирование / Drag мышью), **F6** (Перемещение / Переименование / Shift+Drag мышью) в Total Commander.
    - **Соглашение вызовов (ABI WFX):** Экспорты `FsRenMovFile` и `FsRenMovFileW` принимают строго 5 параметров (`OldName`, `NewName`, `MoveFlags`, `OverWrite`, `RemoteInfoStruct*`) с соглашением `stdcall`. Это обеспечивает точное соответствие стека и предотвращает сбои памяти (Access Violation / `c0000005`) в версии Total Commander 7.50a и новее.
    - **Режим перемещения / переименования (MoveFlags != 0 / F6):**
      - *Внутри одного канала:* Выполняется мгновенно на уровне базы SQLite путем обновления полей `name` и `parent` без затрат сетевого трафика.
      - *Между разными каналами:* Выполняется гибридно и безопасно — файл скачивается во временное хранилище, заново выгружается в целевой Telegram-канал (с сохранением структуры папок), запись в SQLite обновляется новым `mount_id` и `tg_message_id`, после чего старое сообщение в исходном Telegram-канале физически удаляется.
    - **Режим виртуального копирования (MoveFlags == 0 / F5):**
      - *Внутри одного канала:* Создает новую запись файла/папки в SQLite с тем же `tg_message_id`. Это происходит **мгновенно** и с **нулевым расходом сетевого трафика**, эмулируя полное копирование.
      - *Между разными каналами:* Скачивает файл и выгружает в целевой Telegram-канал, создавая новую запись в SQLite и **сохраняя** исходное сообщение и запись в исходном канале.
    - **Работа с директориями:** При перемещении и копировании папок каскадно обрабатываются пути для всего дерева подэлементов. Включена защита от циклического копирования/перемещения папки внутрь самой себя. При конфликтах имён с флагом перезаписи `FS_COPYFLAGS_OVERWRITE` вытесняемый элемент перемещается в корзину `[.Trash]`.
12. **Универсальная нормализация виртуальных путей и регистронезависимость (NormalizeVfsPath & COLLATE NOCASE):**
    - Total Commander может передавать пути в томах VFS как в виде `\ChannelName\Subfolder\file.txt`, так и с префиксом имени плагина `\\\tgvfsplugin\ChannelName\Subfolder\file.txt`.
    - Все точки входа WFX (`FsRenMovFile`, `FsPutFile`, `FsGetFile`, `FsDeleteFile`, `FsRemoveDir`, `FsMkDir`, `CreateStateForPath`) используют единую функцию нормализации `NormalizeVfsPath`. Она определяет наличие префикса имени тома/плагина, сверяет сегменты с точками монтирования в SQLite и корректно выделяет название канала и виртуальный подпуть.
    - Все поисковые SQL-запросы к базе SQLite (`GetMountByName`, `GetFile`) выполняются с директивой `COLLATE NOCASE`, что обеспечивает независимость от регистра букв при операциях чтения, записи, переименования и перемещения файлов (F5/F6) в Total Commander.


## 6. Установка в Total Commander

1. Скачайте `.zip` архив с плагином (например, из раздела Releases в GitHub).
2. Запустите Total Commander.
3. Найдите скачанный архив на одной из панелей, **выделите его курсором и нажмите `Enter`** (или дважды кликните по архиву левой кнопкой мыши).
4. Total Commander автоматически обнаружит конфигурацию и предложит установить плагин — нажмите "ОК"/"Да" на всех этапах.
5. После установки перейдите в **Сетевое окружение** (кнопка `[\]` над панелью или выберите диск "Сеть/FS-плагины") — там появится папка `Telegram VFS`.

## 7. Локальное кэширование и конфигурация (Storage & Settings)
- **Управление расположением данных (Диалог «[*] Настройки плагина»):**
  Пользователь может в любой момент переопределить расположение всех файлов данных плагина (БД, сессия, логи, настройки):
  1. **По умолчанию (%APPDATA%):** `%APPDATA%\TelegramVFS\` — стандартное системное расположение в профиле пользователя.
  2. **Портативный режим (Portable):** подпапка `Data\` прямо рядом с DLL плагина (удобно при запуске Total Commander с флешки). Конфигурация и все файлы (`settings.ini`, `vfs_cache.db`, `WTelegram.session`) хранятся внутри этой подпапки `Data\`.
  3. **Пользовательская папка (Custom):** любой произвольный каталог на локальном или сетевом диске.
- **Единое монолитное хранение файлов:** Все файлы (`vfs_cache.db`, `vfs_cache.db-wal`, `vfs_cache.db-shm`, `WTelegram.session`, `settings.ini`, `plugin_log.txt`) всегда хранятся вместе внутри активной папки данных. Корень плагина не захламляется дублирующими файлами.
- **Автоматический перенос файлов (Data Migration):** При смене расположения в диалоге настроек плагин автоматически перемещает существующие файлы (включая `settings.ini` со всеми ключами API и телефоном) в новую директорию без потери авторизации и истории.
- **Бесшовный перезапуск (Hot Reload):** При сохранении настроек плагин освобождает дескрипторы базы данных (`SqliteConnection.ClearAllPools()`) и сессии Telegram, обновляет пути и лениво переподключается при следующем обращении к любой виртуальной папке.
- **Локальная БД:** Все данные о каналах, чатах, папках и файлах кэшируются в локальной базе данных SQLite (`vfs_cache.db`).
- **Сессия:** Библиотека `WTelegramClient` сохраняет ключи сессии в файл `WTelegram.session` в выбранной папке данных, обеспечивая постоянную авторизацию.
- **Настройки (settings.ini):** Конфигурация плагина хранится в INI-файле (`storage_mode`, `data_path`, `api_id`, `api_hash`, `phone_number`).
- **Логирование:** Вся техническая информация пишется в `plugin_log.txt`.

## 8. Стандарты UI/UX и Интеграция с TC
Поскольку плагин работает внутри Total Commander и использует нативные формы Windows (WinForms) для диалогов, мы придерживаемся следующих правил:
- **Шрифт:** Все формы и контролы должны использовать современный шрифт `Segoe UI` размером `9pt` (`Font = new Font("Segoe UI", 9)`).
- **Высота кнопок (Buttons):** Из-за использования нестандартного шрифта автоматический размер кнопок в WinForms может искажаться (сплющиваться). Для всех кнопок в диалоговых окнах (OK, Отмена и т.д.) должна жестко задаваться высота: `Height = 30`.
- **Обновление панелей (RefreshActivePanel):** Окно Total Commander не должно обновляться "просто так" по таймеру или в фоне, так как это вызывает визуальные мерцания и сбивает выделение файлов. Метод `Win32Api.RefreshActivePanel()` (запускающий асинхронную задержку в 100мс перед отправкой сообщения `cm_RereadSource`) должен вызываться **исключительно** как финальный этап успешно завершенной пользовательской операции: авторизации, создания папки/канала, переименования, удаления или загрузки файла.
